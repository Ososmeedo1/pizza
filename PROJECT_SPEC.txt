# PIZZATO — Project Specification

Single source of truth for the PIZZATO pizza-shop catalog. Any conflict between this document and older code comments resolves in favor of this document.

---

## 1. Overview

- **Product:** Bilingual (Arabic / English) online catalog for a pizza shop.
- **Brand:** PIZZATO — Cairo, Egypt (fictional business data).
- **Purpose:** Showcase menu, build orders visually, hand off via Facebook Messenger.
- **No cart, no checkout, no payments, no customer accounts.** Ordering = Messenger handoff.
- **Primary device:** Mobile. Every design and performance decision optimizes for phones first.
- **Codebase origin:** Fork of the desserts-shop catalog. Architecture preserved; brand, data model extensions, and ordering channel changed.

---

## 2. Brand Identity

### 2.1 Voice & Tone
Concise. Confident. Implementation-focused. Short punchy lines. No fluff, no exclamation spam, no cartoonish copy.

### 2.2 Color Palette
| Token role | Hex | Usage |
|---|---|---|
| Near-black | `#000101` | Light-mode foreground / dark-mode background |
| Warm cream | `#fbebdb` | Light-mode background / dark-mode foreground |
| Deep red | `#6b010f` | Brand primary (fills, buttons, badges, active states) |
| Bright red | `#e0565f` | Brand-as-text on dark surfaces only (dark mode) |
| Lifted cream | `#fff6ec` | Light-mode card surface |
| Lifted black | `#151110` | Dark-mode card surface |

Rules:
- `#6b010f` is an accent and fill color, never a page background wash.
- Light mode: brand-as-text uses deep red. Dark mode: brand-as-text uses bright red.
- No pink, no teal, no cold blues anywhere.

### 2.3 Typography
| Role | EN | AR |
|---|---|---|
| Display (hero h1, section h2, wordmark) | Rye | Cairo 900 |
| Overlines, badges, buttons | Montserrat 800, uppercase, tracked | Cairo 700 |
| Card/product titles | Montserrat 700 | Cairo 700 |
| Body / UI | Montserrat 400–600 | Cairo 400–600 |

Rules:
- Fluid type scale via `clamp()` (mobile-first minimums).
- `letter-spacing: 0` on all Arabic text, always. Uppercase + tracking on Latin only.
- Line-height 1.2–1.3 minimum on Rye headings (ornament clipping check mandatory).

### 2.4 Design System: Modern Claymorphism
- Rounded 16–24px components.
- Soft layered clay shadows (near-black warm tint in light mode, pure black in dark mode).
- Warm depth, no harsh borders, no glassmorphism, no heavy gradients.
- Spacious but never empty. Product photography is the hero.
- Decorative elements: max 2 per section, low opacity, purposeful.
- The UI must look correct with decorations disabled.

### 2.5 Hard Design Rules
- Mobile-first always. If an effect helps desktop but hurts mobile, remove it.
- No hover-dependent interactions (mobile has no hover). Tap/focus parity mandatory.
- 44px minimum touch targets.
- Transitions 200–400ms. Respect `prefers-reduced-motion`.
- Arabic RTL and English LTR compositions must both feel designed, not mirrored by accident.

## 3. Tech Stack & Architecture

- Next.js App Router (Server Components by default), JavaScript only (no TypeScript).
- MongoDB + Mongoose. ImageKit for media. Vercel hosting. next-intl for i18n. Auth.js for admin session.
- React Hook Form + Zod for all forms.
- No new dependencies unless provably necessary.
- Public storefront: ISR (revalidate 300s / 3600s) + on-demand `revalidatePath` invalidation on admin writes.
- Admin and auth: always dynamic, never publicly cached.
- Products listing stays dynamic (searchParams).
- MongoDB indexes: slug uniques, `{isActive, sortOrder, createdAt}`, `{category, isActive, sortOrder}`, `{isFeatured, isActive, sortOrder}`, category `{isActive, sortOrder}`.
- Images: ImageKit custom loader (`w-{width},q-80,f-auto`), `next/image` with correct `sizes`, `priority` only for genuine LCP images.

## 4. Data Model

### 4.1 Category
- `name {ar, en}`, `slug`, `description {ar, en}`, `image {url, fileId, alt{ar,en}}`, `isActive`, `sortOrder`.
- **NEW:** `parent` — optional self-reference. Enables two-level hierarchy.
- Parent pages list descendant products and expose child filter chips.

### 4.2 Product
- `name {ar,en}`, `slug` (auto), `category` (ref), `price`, `oldPrice?`, `description {ar,en}`, `images[] {url, fileId, alt{ar,en}}` (alt auto = product name), `isActive`, `isAvailable`, `isFeatured`, `sortOrder`.
- `measuringUnit { unitType: 'weight'|'pieces'|'size', options[] { name{ar,en}, key?, price, isActive, sortOrder } }`, `hasMeasuringUnit` (derived: options.length > 0).
  - For pizzas: `unitType = 'size'`, option keys `S | M | L`. Products may define only a subset (e.g., M/L only).
- **NEW:** `ingredients: [{ar, en}]` — structured main-ingredient tags.
- **NEW:** `isNew: Boolean` — drives the "New" badge.
- Embedded per-product add-ons: **REMOVED** (replaced by global AddOn collection).

### 4.3 AddOn (global collection — NEW)
- `name {ar,en}`, `priceMode: 'flat' | 'bySize'`, `price` (flat), `sizePrices {S?, M?, L?}`, `isActive`, `sortOrder`.
- Managed once in admin. All active add-ons apply to pizza products.
- On product pages, an add-on's displayed/charged price resolves from the selected size key; flat add-ons ignore size.

### 4.4 SiteSettings
- `brandName {ar,en}`, `logo`, `favicon`, `contactMessage {ar,en}`, `address {ar,en}`, `openingHours {ar,en}`, `phone`, `email`, social links.
- **CHANGED:** `messenger` (URL or username → `https://m.me/...`) **replaces** `whatsapp` as the shop ordering channel.
- `mapUrl` (Google Maps link) retained for the contact directions button.

### 4.5 Admin
- Single-admin model, session-based auth, setup-token registration.

## 7. Ordering Flow (Messenger)

1. Customer selects size + add-ons on the product page. Live total updates.
2. "Order via Messenger" button:
   - Copies the order summary (product, size, add-ons, total) to the clipboard.
   - Opens `https://m.me/{settings.messenger}` in a new tab.
   - Shows a toast: "Order copied — paste it in Messenger."
3. Mobile: sticky bottom CTA mirrors the main CTA (single shared state, one visible CTA per viewport).
4. If messenger is unconfigured: CTA disabled with clear messaging. Never fabricate a contact.

---

## 8. Storefront Specification

Pages: Home, Products listing (search + category filter + pagination 12/page), Product detail, Category pages (parent shows child chips), Add-ons listing, About, Contact.

Home sections (mobile order): Header → Hero → Featured pizzas → Categories → Sides & Salads spotlight → Why PIZZATO → Social → Contact CTA → Footer.

Product detail shows: gallery, name + New badge, category, price (or From-price), size selector (radio pills), **Main Ingredients** tag block, add-ons checkboxes with size-resolved prices, live total, description, Messenger CTA.

Badges: `New` (brand fill), `Sold Out` (neutral). No price badges.

Hero: compact on mobile, editorial on desktop, strong focal imagery, no 90vh, CTA above the fold.

---

## 9. Admin Specification

- Dashboard, Products CRUD, Categories CRUD (with **parent select**), **Add-Ons CRUD** (flat or bySize pricing), Settings, image uploads via ImageKit.
- Product form: ingredients chip editor (ar+en per tag), `isNew` toggle, measuring-unit editor with size keys, add-ons section removed (global now).
- Slug and alt text auto-generated. No manual inputs.
- Pagination 10/page on product list.
- All mutations trigger targeted `revalidatePath` invalidation.

---

## 10. i18n / RTL

- Arabic default locale. Full parity of keys (en/ar synced).
- Logical CSS properties only (start/end, ms/me, ps/pe).
- Both directions composed intentionally; verify visually, not just mirrored.

---

## 11. SEO & Caching

- ISR: home/product/category/contact 300s; about/sitemap 3600s; listing dynamic.
- On-demand invalidation on every admin mutation (products, categories, add-ons, settings).
- Canonical + hreflang (ar/en/x-default) on every public route. Paginated pages `noindex`.
- Product JSON-LD with escaped serialization.
- Admin/auth never cached.

---

## 12. Accessibility & Performance Targets

- WCAG AA contrast in both modes (brand-as-text splits deep/bright red per mode).
- 44px touch targets; visible focus states; skip link; semantic headings; single h1 per page.
- Mobile LCP < 2.5s on 4G. Card images ≤ ~640w renditions; gallery ≤ 1200w; q-80; f-auto.
- Zero layout shift from images. Cached storefront pages must not query MongoDB per visitor.

---

## 13. Constraints

- JavaScript only. No TypeScript. No new dependencies.
- No Redis, no external cache, no custom frameworks.
- No fake business claims beyond the fictional seed data defined here.
- Do not redesign unrelated surfaces when executing focused tasks.
- Every task ends with: lint 0 warnings, build pass, residue cleanup, report.
